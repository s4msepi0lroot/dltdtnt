# Vital Stages — MVP для Minecraft Java 1.21.1 / NeoForge

Полный исходный проект, а не набор фрагментов. Java 21; NeoForge **21.1.233**; ModDevGradle **2.0.143**; для локальной сборки Gradle **9.2.1**. Mod ID: `vitalstages`.

**Статус:** разработанный MVP-кандидат, не сертифицированный production-релиз. Реально выполнены 41 700 проверок чистой Java-модели (включая 10 000 случайных шагов), синтаксическая проверка Java 21 и проверка JSON/TOML. Полная компиляция Minecraft/NeoForge и запуск игры НЕ выполнены: загрузка внешних зависимостей была недоступна. См. `VALIDATION_RU.md`. До публичного релиза обязательны сборка и интеграционные проверки.

## С чего начать

- `MVP_CODE_RU.md` — **полный код** в запрошенном порядке **a → g**, затем все вспомогательные файлы, конфиг и ресурсы. Без многоточий вместо реализаций.

## Сборка и запуск

Установите **JDK 21** и **Gradle 9.2.1**, задайте `JAVA_HOME` на JDK 21. Для первого запуска нужен интернет к Gradle Plugin Portal, NeoForge Maven и Minecraft/Mojang. В корне проекта:

```sh
gradle --no-daemon build
gradle runClient
gradle runServer
```

Результат: `build/libs/vitalstages-0.1.0.jar`. JAR нужно установить **на сервер и на все клиенты**. Для сервера примите Minecraft EULA только после самостоятельного ознакомления с ней; проект этого автоматически не делает.

Бинарный Gradle Wrapper в архив не подложен и готовый JAR не сфабрикован. При установленном Gradle можно создать официальный wrapper:

```sh
gradle wrapper --gradle-version 9.2.1
./gradlew build
```

Либо используйте включённый GitHub Actions workflow после загрузки проекта в свой репозиторий: он устанавливает JDK/Gradle и запускает `build`. Этот workflow подготовлен, но ещё не исполнялся в вашем репозитории.

Чистые тесты модели, без скачивания Minecraft:

```sh
sh scripts/test-core.sh
```

## Архитектурные решения

### Attachment + Capability, а не две копии организма

`PlayerHealthData` хранится в сериализуемом `AttachmentType`. `EntityCapability<HealthView, Void>` возвращает read-only интерфейс того же объекта **на сервере**. Сериализацию выполняет attachment. Старые Forge `LazyOptional`, `AttachCapabilitiesEvent` и `reviveCaps()` не используются.

На клиенте работает отдельный визуальный snapshot; capability намеренно не возвращает там несинхронизированное локальное состояние. Клиент не может отправить «я здоров» на сервер.

### HP и смерть

Vanilla HP остаётся источником обычного здоровья, поэтому лечение зельями, едой и другими корректными vanilla-путями продолжает работать. Поле `health` в attachment — синхронизируемый снимок, не независимая вторая шкала.

При первом обычном смертельном ударе отменяется `LivingDeathEvent`, ставится `criticalTrauma` и запускается обморок. Vanilla HP временно удерживается на техническом положительном минимуме (обычно 1), но физиологическое `health` при этом показывается как 0. Нельзя хранить живого игрока с настоящим vanilla HP=0: сломаются `isAlive`, тики и взаимодействие напарника.

`criticalTrauma` снимается, когда настоящий vanilla HP восстановлен до `reviveHealth` (обычно 4, с учётом max-health). Бинт HP не восстанавливает: при таком обмороке нужен ещё источник лечения, например бросаемое зелье лечения. При обмороке от боли/активной потери крови достаточно своевременной стабилизации, если остаток крови жизнеспособен.

### Цепочка состояний

```text
CONSCIOUS (C >= 35)
       ↓
PRESYNCOPE (0 < C < 35): усиливается виньетка
       ↓ C = 0 или сорванная обычная смерть
UNCONSCIOUS: blackout + блокировка действий + окно до 60 игровых секунд
       ├─ стабилизация + C >= 10 + минимум 40 тиков → PRESYNCOPE/CONSCIOUS
       └─ кровь = 0 ИЛИ окно истекло → настоящий hurt/die/LivingDeathEvent
```

Порог выхода отличается от порога входа — это гистерезис. Положительное сознание во время восстановления ещё не означает немедленного возврата управления.

Смерть при нулевой крови может наступить **раньше** конца таймера. Окно спасения — верхняя граница, не 60 секунд неуязвимости. Повторные удары не перезапускают его. Финальный источник `vitalstages:organ_failure` обходит броню/неуязвимость/тотем; другие моды всё ещё могут отменить сам death event. Повтор такой попытки ограничен одним разом в секунду, а рекурсивный флаг очищается в `finally`.

`/kill`, пустота и остальные источники с `bypasses_invulnerability` намеренно пропускают промежуточную стадию. Обычный тотем работает до обычного `LivingDeathEvent`, но не восполняет медицинскую кровь и не отменяет уже полученные раны.

### Урон и раны

`LivingDamageEvent.Pre` уменьшает остаточный урон множителем `healthDamageFraction=0.6`. В NeoForge 1.21.1 это после брони/эффектов, но до absorption. Следовательно, жёлтые сердца поглощают уже преобразованный урон — осознанное правило MVP.

Раны создаются в `LivingDamageEvent.Post` только при `getNewDamage() > 0`, после absorption. Щит/полное поглощение/нулевой конечный урон не порождают скрытых порезов. Тип: падение — ноги/ушиб или перелом; огонь — ожог; снаряды/взрыв/острое оружие — порез; асфиксия/голод/магия — без наружной раны. У мобов ближний бой условно считается режущим; это упрощение можно заменить таблицей damage-type/weapon tags.

Одна агрегированная рана каждого типа на участок: максимум 24 записи. Повторное попадание складывает тяжесть с ограничением и заново открывает перевязанную рану. Это контролирует размер NBT/обработки. Для независимых отдельных порезов понадобится ограниченный список с собственной стратегией объединения.

`bleedingRate` пересчитывается из ран; хранить её только через `+=` нельзя — бинт, reload или смена настроек дадут дрейф. `blood -= bleedingRate / 20` на каждом серверном игровом тике. Кровь самостоятельно не восстанавливается. Limb-status выводится из ран, а не сохраняется второй расходящейся копией.

## Как пользоваться бинтом

- Крафт: **любая шерсть + нить → 4 бинта** (бесформенный).
- ПКМ в воздух — перевязать себя; ПКМ по игроку — оказать помощь.
- Сервер выбирает самый опасный открытый CUT по его вкладу в кровопотерю.
- Дистанция — не более 3 блоков, тот же мир, прямая видимость, оба игрока живы.
- Без сознания нельзя лечить себя; напарник без сознания также не может оказывать помощь.
- Одна успешная перевязка тратит один бинт (кроме creative), cooldown — 30 тиков.
- При отсутствии открытого CUT предмет не расходуется.
- Бинт не добавляет HP, кровь или сознание напрямую и не лечит инфекцию.

Для получения в тестовом мире:

```mcfunction
/give @s vitalstages:bandage 16
```

Модель предмета использует встроенную vanilla-текстуру бумаги как временную иконку, чтобы не включать чужие бинарные ассеты. Собственный арт — отдельная задача.

## Жизненный цикл и безопасность

- **Logout/reconnect:** NBT сохраняет кровь, все раны, сознание, критическую травму и использованные тики окна. Офлайн симуляция намеренно приостановлена. Перезаход не лечит и не выдаёт новое окно, но позволяет поставить опасность на паузу — явная политика MVP, не anti-combat-log система.
- **Смена измерения:** состояние не очищается; отправляется полный snapshot. Не-смертельный clone при возвращении из End получает копию без дублирования ран.
- **Настоящий respawn:** создаётся новый организм. Это единственный штатный полный сброс.
- **Creative/spectator:** физиология приостановлена, UI/блокировка отключены, медицинское состояние не стирается.
- **Сеть:** только S2C; изменение показателей вычисляет сервер. Бинт использует штатные взаимодействия Minecraft, поэтому отдельный C2S для лечения в MVP не нужен. При login/respawn/dimension/лечении/уроне идёт snapshot, регулярно — раз в 5 тиков.
- **Блокировка:** клиент обнуляет movement input, interaction keys и фиксирует камеру. Серверный mixin блокирует атаки, использование, бросание, swaps, инвентарь и управление транспортом. Горизонтальный ход/поворот фильтруются сервером; вертикальная физика остаётся vanilla-проверкой. Внешние модовые C2S и `/tp`-подобные привилегированные команды — не область защиты этого MVP.
- **Нет softlock:** KeepAlive, teleport confirmation, чат, команды и меню выхода не блокируются. Не вызывается `setGameMode(SPECTATOR)`.
- **NBT:** версия формата, defaults для отсутствующих ключей, ограничения чисел/списков, NaN/Infinity sanitization, безопасный разбор enum. Downgrade из будущего формата завершается явной ошибкой, а не молча стирает состояние.
- **Производительность:** максимум 24 агрегата ран на игрока, компактный owner-only пакет, отсутствуют глобальные Map с сильными ссылками на ушедших игроков.

## Конфигурация и границы MVP

`<world>/serverconfig/vitalstages-server.toml` создаётся NeoForge. Полный перечень и ranges — в `HealthConfig.java`.

Реально работают кровь, боль, сознание, окно смерти, POC-виньетка, бинт и хранение состояний конечностей. `enableFractures` управляет созданием FRACTURE, но пока не добавляет штрафы. `enableTemperature=false` и `enableInfection=false` по умолчанию: при включении первого учитывается сохранённая температура в сознании, при включении второго идут таймер/накопление риска раны. Климатической симуляции и заболевания инфекции ещё нет. Эти ограничения указаны и в комментариях TOML-конфига.

Обычная регенерация HP может помочь очнуться, но не возвращает кровь и не закрывает раны. Реалистичность здесь — игровая абстракция, а не медицинская симуляция.

## Следующие шаги — НЕ вошли в MVP

1. Полные переломы: стабильные attribute modifiers, влияние рук на атаки/точность, шины, срок сращивания, удаление заживших ран.
2. Температура: теплообмен с биомом, водой, погодой, экипировкой и огнём; отдельные зоны гипо-/гипертермии. Сейчас хранится температура и опционально учитывается её штраф.
3. Инфекция как заболевание: реализовать переход накопленного риска в инфекцию, симптомы, антисептик и лечение. В MVP есть только пер-рановый таймер и расчёт риска.
4. Полный анатомический HUD и выбор конкретной раны. Новый C2S должен передавать только намерение/ID раны; расстояние, предмет, доступность и стоимость повторно проверяются сервером.
5. Жгуты с ишемией/некрозом и снятием, обезболивающие, адреналин, дефибриллятор, пополнение крови. Адреналин не должен создавать кровь или стирать повреждения.
6. Перенос пострадавшего и аптечка-блок: отдельная серверная механика транспортировки/стабилизации/точки восстановления. Различать «доставили живым» и настоящий death-respawn.
7. Post-processing shader: десатурация, двоение, размытие; корректное управление своими render targets, resize/reload и совместимость с чужими post-chain/Sodium/Iris/Oculus-портами.
8. Пульс, шёпот, декоративные клиентские фантомы, дозированная тряска камеры; настройки доступности, интенсивности и отказ от насильственной инверсии управления по умолчанию.
9. Интеграционные GameTests, настоящий dedicated-server smoke test с двумя клиентами, совместимость с death/gravestone/health/anti-cheat модами, долгий нагрузочный прогон и баланс.
10. Уточнённые направленные попадания и отдельная физика обездвиженного тела. Текущий серверный фильтр движения — ограничение ввода, не ragdoll и не полноценный anti-cheat.
