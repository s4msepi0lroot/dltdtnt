# 01. Как всё устроено

## Идея

Мод даёт локальный кооп: два персонажа управляются с одной клавиатуры
(P1 — `WASD, Z, X, P, C, Ctrl, Shift`; P2 — `стрелки, Enter, Ctrl, Shift, C`).
DeltaDotNet не трогает мод вообще. Он делает две вещи:

1. **Стримит** окно игры с компьютера хоста всем участникам лобби.
2. **Принимает** нажатия гостей и синтезирует их на клавиатуре хоста через
   WinAPI `SendInput`, подставляя ту клавишу, которую мод ждёт для конкретного
   слота игрока.

Для мода это выглядит как обычная игра вдвоём за одним компьютером.

## Три приложения

```
┌──────────────────────────┐        ┌────────────────────────┐
│ DeltaDotNet.exe (WPF)    │        │ DeltaDotNet.ThemeStudio│
│ хост И гость одновременно│        │ редактор .ddntheme     │
└─────────────┬────────────┘        └───────────┬────────────┘
              │ HTTP + WebSocket                │ пишет .ddntheme в
              ▼                                 ▼ %AppData%\DeltaDotNet\themes
┌──────────────────────────┐
│ server (Node.js)         │
│ express + ws, без БД     │
└──────────────────────────┘
```

## Роли

| Роль | Что делает |
|---|---|
| **Хост** | владелец лобби. У него запущены игра и мод. Он захватывает экран, шлёт кадры, инжектит чужой ввод, может кикать/банить, менять слоты, закрывать лобби |
| **Гость** | видит стрим, шлёт свои нажатия. Кнопки настраивает под себя |
| **Админ** (`s4msepi0l`) | видит всех пользователей, выдаёт радужные ники, бейджи, ранги, баны, гасит чужие лобби, шлёт broadcast |

## Как ввод превращается в нажатие в игре

Самая важная часть проекта — три уровня клавиш:

```
  клавиша на клавиатуре гостя      →  действие         →  клавиша слота у хоста
  (MyBinds, у каждого свои)           (Up/Confirm/...)    (SlotGameKeys, у хоста)

  например у гостя стрелка Вверх   →  Up               →  слот 2: клавиша Up
  а у другого гостя клавиша I      →  Up               →  слот 3: клавиша NumPad8
```

Действий десять: `Up, Down, Left, Right, Confirm, Cancel, Menu, Special, Run, Ctrl`.

Поэтому гость может назначить себе любые удобные кнопки — сеть ничего не знает о
физических клавишах, она передаёт только действие и `down/up`.

Дефолты слотов (`Core/Keybinds.cs`):

| Действие | Слот 1 | Слот 2 |
|---|---|---|
| Up / Down / Left / Right | `W / S / A / D` | `Up / Down / Left / Right` |
| Confirm | `Z` | `Return` |
| Cancel | `X` | `RightCtrl` |
| Menu | `C` | `C` |
| Special | `P` | — |
| Run | `LeftShift` | `RightShift` |
| Ctrl | `LeftCtrl` | `RightCtrl` |

Слоты 3–8 пустые: заполняйте их в **SETTINGS → MOD KEYS**, если ваша сборка мода
умеет больше двух локальных игроков.

## Видео

- Захват: GDI `BitBlt` окна/экрана/области (`Core/ScreenCapture.cs`).
- Кодирование: JPEG (`JpegBitmapEncoder`), качество и масштаб — из настроек.
- Передача: бинарный WS-кадр `0x01 + uint64 timestamp + JPEG`.
- Сервер только пересылает кадр всем гостям лобби, ничего не декодирует.
- Гость показывает **только последний** кадр, старые выбрасываются — так стрим
  не «отстаёт» при лагах.

Пресеты качества: Potato (10 fps / 40 % / q35), Low (20/55/45), Medium (30/75/62),
High (45/90/75), Ultra (60/100/88) + полностью ручной режим.

## Хранение данных

- Сервер: один JSON-файл (`server/data/db.json`), никакой БД ставить не нужно.
- Клиент: `%AppData%\DeltaDotNet\config.json`, темы — `%AppData%\DeltaDotNet\themes\`,
  ошибки — `crash.log`.
