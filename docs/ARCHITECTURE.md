# Архитектура DeltaDotNet

## Общая схема

```
         ХОСТ (Windows)                 РЕЛЕЙ (Node.js)              ГОСТИ
  ┌─────────────────────────┐      ┌───────────────────┐      ┌──────────────┐
  │ ScreenCapturer      │─JPEG─│ пересылка кадров │─JPEG─│ ViewerForm   │
  │ InputInjector       │←────│ валидация input │←────│ клавиатура   │
  │ HostForm            │      │ лобби, авториз.│      │              │
  └─────────────────────────┘      └───────────────────┘      └──────────────┘
```

Релей не знает ничего об игре: он только держит учётки, лобби и права,
проверяет действия по белому списку и пересылает байты.

## Сервер

Чистый Node.js без зависимостей. Пять модулей:

| Модуль | Отвечает за |
|--------|--------------|
| `src/ws.js` | своя реализация WebSocket: рукопожатие, кадры, ping/pong, бекпрешер |
| `src/store.js` | учётки в JSON-файле, scrypt-хеши, роли, баны, украшения ников |
| `src/auth.js` | подписанные токены (HMAC), чтобы не вводить пароль каждый раз |
| `src/lobby.js` | лобби, слоты P1-P4, режимы доступа, баны внутри лобби |
| `src/index.js` | HTTP `/health`, разбор всех сообщений протокола, права, админ-команды |

Права проверяются только на сервере: клиент лишь прячет кнопки.
Любая admin-команда от не-админа получает `forbidden`, команды хоста от гостя — `not_host`.

### Жизненный цикл лобби

1. `create_lobby` — хост получает код и слот P1.
2. `join_lobby` — сервер проверяет бан, режим доступа, пароль/список, свободные слоты.
3. `start` — хост шлёт кадры, гости шлют `input`.
4. Завершение: `close_lobby`, обрыв связи хоста или `admin_close_lobby`.
   Всем уходит `lobby_closed`, состояние очищается.

### Защита от перегрузки

Кадр больше `MAX_FRAME_KB` рвёт соединение. Если у гостя в буфере сокета
скопилось больше 4 МБ, кадр ему просто пропускается — медленный клиент
не тормозит остальных.

## Клиент

.NET 8 + WinForms, собирается в один self-contained exe.

| Слой | Файлы |
|------|--------|
| Сеть | `Net/RelayClient.cs` — WebSocket с резервным ручным рукопожатием |
| Захват | `Capture/ScreenCapturer.cs` — снимок окна/экрана и упаковка в JPEG |
| Ввод | `Input/InputInjector.cs`, `Input/KeyMap.cs`, `Input/Bindings.cs` |
| Интерфейс | `Forms/*.cs` |
| Оформление | `Ui/DeltaTheme.cs`, `Ui/DeltaAssets.cs`, `Ui/RainbowText.cs` |
| Настройки | `AppConfig.cs` — `%APPDATA%\DeltaDotNet\config.json` |

Ввод подставляется через `SendInput` скан-кодами, поэтому игра видит их как
настоящие нажатия клавиатуры. При потере связи или фокуса вызывается
`ReleaseAll()`, чтобы клавиша не осталась зажатой.

## Почему свой WebSocket и резервное рукопожатие

Сервер не тянет npm-зависимостей — его легко положить куда угодно.
На клиенте штатный `ClientWebSocket` иногда падает с ошибкой
`Sec-WebSocket-Accept ... is invalid` из-за сторонних фильтров трафика,
поэтому `RelayClient` умеет выполнить рукопожатие вручную по голому сокету.

## Тесты

`server/e2e-test.js` поднимает настоящий сервер на отдельном порту и прогоняет
11 сценариев: рукопожатие, авторизация, лобби, трансляция, кик, бан, закрытые
лобби, закрытие лобби, админка, серверный бан и защита учётки владельца.
Запуск: `node server/e2e-test.js`.
