# Архитектура CoopStream

## Общая схема

```
ИГРОК 1 (хост, Windows)                 СЕРВЕР (Node.js)            ИГРОК 2 (гость, Windows)
┌────────────────────────────┐        ┌─────────────────┐      ┌─────────────────────┐
│ Игра (локальный кооп-мод)     │        │ HTTP /health    │      │ ViewerForm         │
│   ▲ SendInput   ▲ клава хоста  │        │ WS   /ws        │      │  • PictureBox      │
│   │              │              │        │                 │      │  • перехват клавиш │
│ HostForm                       │        │ UserStore       │      └─────────────────────┘
│  • ScreenCapturer ──JPEG───────┼──bin───► LobbyManager ───bin──► кадры
│  • InputInjector ◄──────────────┼──json─── TokenService ◄──json─ нажатия
└────────────────────────────┘        └─────────────────┘
```

Сервер — чистый релей: он не декодирует кадры и не знает об игре. Он только:
1. проверяет, кто вы (логин/пароль → токен);
2. держит лобби на двух участников;
3. пересылает байты второму участнику, проверяя белый список клавиш и направление потока.

Поэтому ему хватает самого дешёвого VPS: CPU почти не нужен, важен только канал.

## Почему именно так

| Решение | Причина |
|---|---|
| Не P2P, а релей | не нужен проброс портов/STUN/TURN, IP игроков друг другу не видны |
| Свой WebSocket без `ws` | ноль зависимостей → `git clone && node src/index.js` работает везде |
| JPEG-кадры, а не H.264 | нет внешних кодеков и ffmpeg; просто и предсказуемо |
| WinForms + GDI+ | входит в .NET, собирается одной командой в один exe |
| `SendInput` со скан-кодами | игры читают скан-коды (DirectInput), а не виртуальные коды |
| Белый список клавиш в 3 местах | гость физически не может нажать Alt+F4 или Win на чужой машине |

## Потоки данных

### Видео (хост → гость)

1. `ScreenCapturer.CaptureFrame()` — `Graphics.CopyFromScreen` в переиспользуемый `Bitmap`.
2. Масштабирование до `MaxWidth`, сжатие в JPEG.
3. К 17-байтовому заголовку (тип, номер, ширина, высота, время) клеится JPEG.
4. `RelayClient.SendBinaryAsync` → WS binary → сервер проверяет «это хост и сессия идёт» → гостю.
5. `ScreenCapturer.TryParse` → `PictureBox.Image`.

Защита от перегрузки:
- хост не начинает следующий кадр, пока не ушёл предыдущий (флаг `_sending`);
- сервер дропает кадр, если буфер гостя > 4 МБ (лучше пропустить кадр, чем копить задержку).

### Ввод (гость → хост)

1. `ViewerForm.ProcessKeyPreview` ловит `WM_KEYDOWN/WM_KEYUP`, берёт скан-код и флаг extended из `lParam`.
2. `KeyMap.FromScan` → имя клавиши (`"Left"`, `"RShift"`…). Автоповтор отбрасывается.
3. `KeyPolicy.IsAllowed(роль, клавиша)` — первая проверка.
4. JSON `{t:"input", key, down}` → сервер — вторая проверка (`ALLOWED_KEYS`).
5. `HostForm.HandleJsonFromBackground` — третья проверка → `InputInjector.Send` → `SendInput`.

Сообщение `release_all` шлётся при потере фокуса, закрытии окна и обрыве связи,
чтобы на стороне хоста не осталась «зажатая» клавиша.

## Жизненный цикл лобби

```
create_lobby → [waiting] ─join_lobby→ [full] ─start→ [running] ─stop/отключение→ [full/удалено]
```

- Лобби живёт только в памяти: рестарт сервера их очищает (аккаунты сохраняются).
- Выход хоста закрывает лобби (`lobby_closed`), выход гостя — просто освобождает слот (`peer_left`).
- В лобби ровно два места; третий получит `lobby_full`.

## Безопасность

- Пароли — `scrypt` с индивидуальной солью, сравнение через `timingSafeEqual`.
- Токены — HMAC-SHA256 от `AUTH_SECRET`, срок жизни 7 дней. Смена секрета разлогинивает всех.
- До авторизации разрешены только `register`, `login`, `auth_token`, `ping`.
- `ALLOW_REGISTER=0` закрывает регистрацию после создания нужных аккаунтов.
- Бинарные кадры идут только в направлении хост → гость; обратно сервер их не пропускает.
- Для шифрования трафика поставьте nginx/Caddy с TLS и используйте `wss://` (см. DEPLOY.md).

## Структура репозитория

```
coop-stream/
├─ server/
│  ├─ src/
│  │  ├─ ws.js        — реализация WebSocket (RFC 6455)
│  │  ├─ store.js     — хранилище пользователей (scrypt)
│  │  ├─ auth.js      — токены HMAC
│  │  ├─ lobby.js     — лобби и коды
│  │  └─ index.js     — HTTP + маршрутизация сообщений
│  ├─ test/e2e.js     — сквозной тест (запускается в CI)
│  ├─ Dockerfile
│  └─ .env.example
├─ client/CoopStream.Client/
│  ├─ Program.cs
│  ├─ AppConfig.cs
│  ├─ Net/RelayClient.cs
│  ├─ Input/{KeyMap.cs, InputInjector.cs}
│  ├─ Capture/ScreenCapturer.cs
│  └─ Forms/{MainForm.cs, HostForm.cs, ViewerForm.cs}
├─ .github/workflows/build.yml
└─ docs/
```
