# Архитектура DeltaDotNet

## Составные части

| Часть | Технология | Зачем |
| --- | --- | --- |
| `server/` | Node.js 18+, без зависимостей | relay: авторизация, лобби, пересылка |
| `client/` | C# .NET 8, WinForms | захват экрана, ввод, интерфейс |
| `.github/workflows/` | GitHub Actions | сборка exe, тесты, релизы |

Клиент один на всех: кто создал лобби — хост (P1), кто вошёл — гость (P2–P4).

## Схема потоков

```
  Гость P2        Гость P3        Гость P4
     |                |                |
     +--- действия ---+--- действия ---+
                      |
               [ relay-сервер ]  ← единственная точка встречи
                      |
                 Хост (P1)
                      |
         SendInput → окно игры → захват экрана
                      |
         JPEG-кадр → relay → все гости
```

Ни один клиент не знает IP другого — P2P нет по замыслу.

## Путь одного нажатия

```
1. Гость жмёт физическую клавишу
2. ViewerForm читает scan-код из WM_KEYDOWN (не символ — раскладка не важна)
3. KeyMap: scan → имя клавиши ("Left", "NumPad4", ...)
4. Bindings гостя: имя клавиши → действие ("Left")
5. По сети: {"t":"input","action":"Left","down":true}
6. Сервер добавляет role/login и шлёт хосту
7. HostForm берёт Bindings для этой роли: действие → имя клавиши
8. InputInjector: имя → scan-код → SendInput в игру
```

Ключевой момент: шаги 4 и 7 независимы. Гость меняет свои клавиши когда угодно,
хост — те, которые ждёт мод. Пересогласование не требуется.

## Путь одного кадра

```
таймер (Fps) → BitBlt окна/экрана → масштаб до MaxWidth → JPEG (JpegQuality)
  → заголовок 17 байт → бинарный WebSocket-кадр → relay
  → каждый гость → разбор заголовка → Image → отрисовка NearestNeighbor
```

NearestNeighbor выбран нарочно: пиксельная графика остаётся чёткой.

## Модель лобби на сервере

```
LobbyManager
  └─ Lobby (код из 6 символов)
       ├─ maxPlayers: 2..4
       ├─ слоты P1..Pn → WsConnection
       ├─ running: идёт ли трансляция
       └─ счётчики frames / bytes
```

- Уход гостя → `peer_left`, слот освобождается.
- Уход хоста → `lobby_closed` всем, лобби удаляется.
- Состояние лобби живёт только в памяти; на диске — только учётные записи.

## Авторизация

Пароли — scrypt с индивидуальной солью, сравнение через `timingSafeEqual`.
Токен — собственный формат `base64(payload).base64(HMAC-SHA256)` на `AUTH_SECRET`.
Пользователи хранятся в одном JSON-файле (`DATA_FILE`).

## Защита от перегрузки

| Механизм | Значение |
| --- | --- |
| Максимальный кадр | `MAX_FRAME_KB`, по умолчанию 2048 КБ |
| Пропуск кадра | если буфер гостя > 4 МБ |
| Heartbeat | ping каждые 20 с, молчащие соединения рвутся |
| Автоповтор | отсекается на клиенте гостя |

## Слои клиента

```
Forms/    — окна (Main, Host, Viewer, Bindings)
Ui/       — тема Deltarune и собственные контролы
Net/      — WebSocket-клиент с резервным рукопожатием
Capture/  — захват экрана и разбор кадров
Input/    — таблица клавиш, привязки, SendInput
AppConfig — хранение настроек в %APPDATA%
```

## Границы решения

- Звук не передаётся.
- Клиент работает только на Windows (WinForms + SendInput).
- Задержка равна двойному пути до сервера — ставьте relay географически между игроками.
- Игра на хосте должна иметь фокус, иначе SendInput попадёт не в то окно.
